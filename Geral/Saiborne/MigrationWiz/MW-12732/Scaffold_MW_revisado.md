# Scaffold MW revisado: impacto de código da Feature 1 (PCH + UMB)

> [!summary] Conclusão em uma frase
> Todo o fluxo UMB já existe para **Mailbox/OneDrive**, mas o PCH ficou fora dele em três pontos. O catálogo de licenças não tem a feature PCH. O line item PCH (`ConversationLineItem`) não tem binding com o CustomerEndUser. A UI desliga as ações por `isTeamsPCH` / `isCollaborationChat`. A Feature 1 consiste em **estender esses caminhos existentes ao `ConversationLineItem`**, sem criar arquitetura nova.

Arquitetura completa, tabela de projetos e lista de arquivos novos: [[Scaffold_MigrationWiz_Feature1]].

## 3. Ordem de implementação sugerida (dependências)

1. **Catálogo** (MW-12099): LicensingData.xml (Prod + Germany, master + develop) e `SubscriptionEntitlementManager`. *Sem isso nada mais funciona.*
2. **Persistência**: colunas SQL + entidades Core/Sdk/Access/DTO do `ConversationLineItem`.
3. **Binding**: `ConversationLineItemEventHandler`, `SyncConversationLineItems` e a Activity AEF de catch-up/retroativo.
4. **Apply/Revoke backend**: `LicenseAttachService` + Request PCH, Consume/Revoke (24h + job no Azure) e a tabela Azure de auditoria.
5. **Enforcement**: `PchLicenseValidator` em `CreateBulk` e `GetEstimate` real, mais o feature flag para projetos novos.
6. **UI MW**: Add from MSPC, Apply/Remove, coluna UMB, Start Migration e i18n.
7. **Store** (MW-12747).
8. **Testes** unitários, de API, de integração, AEF e Ember, seguidos de regressão da toolbar (Feature 3).
